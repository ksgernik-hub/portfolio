# PROJECT CONTEXT — KSUSHA GERNIK PORTFOLIO

## 1) Что это за проект

- Статический мультистраничный сайт-портфолио Ксюши Герник.
- Основные цели:
  - презентация проектных кейсов;
  - отдельная страница резюме;
  - контакты и быстрый способ выйти на связь.
- Сайт двуязычный: RU / EN (переключение на всех ключевых страницах).
- Проект временно защищён паролем на клиенте.

---

## 2) Текущий стек и зависимости

- Без фреймворков и сборщиков: `HTML + CSS + vanilla JS`.
- Глобальные стили: `styles.css`.
- На проектных страницах есть локальные встроенные стили (`<style>` в каждом `project-*.html`).
- Скрипты:
  - `script.js` — главная страница (reveal, hover preview в Other Projects, кастомный курсор);
  - `i18n.js` — словарный перевод интерфейса RU/EN;
  - `password-gate.js` — парольный доступ через prompt;
  - `protection.js` — базовая клиентская защита медиа (контекстное меню/drag и т.д.).
- Внешние встраивания в кейсах:
  - `kinescope.io` (видео iframe);
  - `sketchfab.com` (3D iframe).
- Текущий шрифт: **Golos Text**.

## 4) Актуальные UI/UX-решения (важно)

### 4.1 Навигация

- Фон под шапкой убран (прозрачный header, без подложки).
- Для текста шапки используется эффект инверсии на проектных страницах через `mix-blend-mode: difference` (бренд, пункты меню, переключатель языка).
- На мобильной версии в навигации оставлены:
  - только пункт `Resume`;
  - переключатель языка `EN / RU`.

### 4.2 Языки

- Должно быть правило: язык пунктов меню соответствует активному языку страницы.
- Переводы поддерживаются через словарь `i18n.js`.
- Любой новый текст всегда дублировать в RU/EN словаре сразу.

### 4.3 Типографика

- Активный шрифт: **Golos Text**.
- Кейс (uppercase) возвращён, как было в текущем визуальном стиле.
- Hero-заголовок на главной облегчён по весу (более тонкое начертание, чем раньше).

### 4.4 Главная / сетка проектов

- Карточка `else` на главной выровнена по размеру с остальными карточками (не должна быть визуально выбивающимся full-баннером).
- Блок `Soon...` для ремонта техники:
  - проект некликабельный;
  - формулировка без слова `WIP`.
- Один из полноширинных placeholder-блоков (`NEW PROJECT`) скрыт.
- В паре Nefro/Vyborg поменяно расположение по запросу (Vyborg справа, Nefro слева).

### 4.5 Страница резюме

- Блоки опыта оформлены карточками/плашками для лучшей читаемости.
- Блок образования приведён к одной колонке (как и опыт), а не растянут на всю ширину.
- Русская версия резюме: пункты меню должны быть на русском.

### 4.6 Проектные страницы (mobile)

- Исправлен частый кейс с обрезанием квадратных изображений на мобиле:
  - в мобильных правилах используется `height: auto` + `object-fit: contain` для `case`-изображений.
- Цель: избегать нежелательного кропа в квадратных/пограничных форматах.

## 5) Кейc `else` — ключевые изменения

- Контент многократно переставлялся по комментариям, финальная логика:
  - опираться на **имена файлов** (в них зашиты тип/позиция/размер блока);
  - не менять соседние блоки, если задача про конкретную пару.
- Обновления по текстовой части:
  - в проекте убран «концепт» из названия: теперь просто айдентика;
  - описание сокращено до более короткой версии (1 абзац, без лишних техподробностей);
  - кавычки для `else` согласованы по языкам (англ/рус).
- В кейс добавлены iframe-видео в конкретные слоты по имени позиции (замены отдельных `full/square/rect` блоков).

## 7) Контентные и технические ограничения

- Не менять стек (никакого React/Next и т.п.) без прямого запроса.
- Не удалять `i18n.js`, `password-gate.js`, `protection.js`.
- Для проектных медиа придерживаться согласованной схемы нейминга (позиция/размер зашиты в имени).
- В правках по кейсам не трогать неупомянутые блоки.
- Служебные папки (`downloads`, экспортёры, временные скриншоты) не включать в коммиты.

## 8) Известные риски

- `i18n.js` на словарной подмене: легко получить рассинхрон, если забыть добавить новую фразу в оба языка.
- Инверсия (`mix-blend-mode: difference`) зависит от фона и может выглядеть по-разному на сложных изображениях.
- Клиентская «защита медиа» не является реальной защитой от скачивания.
- Из-за локальных `<style>` в каждой проектной странице легко сделать непоследовательные мобильные правила — это нужно проверять вручную.

## 11) Эталонные соотношения блоков (зафиксировано)

- Для пар в кейсах (`big + small`) использовать одно и то же соотношение колонок:
  - `big/small` = **61.5% / 38.5%** (эквивалент `1.23fr / 0.77fr`).
  - Если маленький блок слева: `38.5% / 61.5%` (класс-реверс пары).
- Для квадратных пар:
  - `big-square` и `small-square` оба остаются квадратами (`1:1`), различие только в ширине колонки пары.
  - Никаких локальных `width`-хаκов для отдельных small-square блоков.
- Для прямоугольных пар:
  - `big-rect` + `small-rect` используют те же колоночные соотношения `61.5/38.5`.
  - Никакого ручного уменьшения `small-rect` через отдельные проценты, если это не отдельный явный запрос.
- Правило стабильности:
  - Нельзя исправлять один блок ценой изменения глобального эталона.
  - Сначала сверка с эталоном выше, затем точечная замена только нужной пары.

## 10) Быстрый onboarding для нового чата

Если новый чат начинает работу, ему важно сразу знать:

1. Это живой портфолио-сайт с большим количеством ручных перестановок контента.
2. Главный риск — случайно «починить одно и сломать другое», поэтому правки должны быть точечные.
3. В проектных кейсах ключ к правильной раскладке — названия файлов ассетов.
4. На мобиле сейчас критичны две вещи:
   - лаконичная навигация (Resume + язык);
   - отсутствие кропа квадратных картинок.
5. Любое текстовое изменение сразу синхронизировать в `i18n.js`.
